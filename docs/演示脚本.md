# 现场演示脚本（3–5 分钟）

演示前准备：电脑联网；终端进到仓库目录；Mira 打开到会话"复现 Wu 2019 团队规模与颠覆性研究"；提前跑一遍 `make demo` 确认当天接口额度够用。

## 0:00–0:40 问题

"《自然》2019 年有一篇很有名的论文，说团队越大，论文越不颠覆。组会前一晚，我想自己验证一遍。问题是算这个指标要抓几千万条引用记录，老办法要跑二十多个小时。"

指易拉宝上的两张示意图，一句话讲什么叫颠覆型、什么叫延续型。

## 0:40–1:40 现场跑关键步骤

终端里敲：

```
make demo
```

边跑边讲："它现在从 OpenAlex 随机抽 5 篇论文。每篇只问接口 3 个数，不逐条抓。"

等输出出来，指"自检"那几行："同样这 5 篇，再用笨办法逐条数一遍，两种办法的结果必须一样。一致才算数。"

## 1:40–2:40 在 Mira 上怎么跑的

切到 Mira，点"Progress"打开任务图："五个成员。文献核对和数据抓取并行；统计分析之后，必须由独立审核员另写一套代码重算。"

往上翻到审核员那条："四个斜率和原流程差不到 1e-16。"

讲一处人工改动："自动生成的流程里漏掉了审核员，让分析的人自己验自己，这是我手动改的。"

## 2:40–3:40 结果

终端里敲：

```
make repro
```

指输出："判定标准是抓数据之前写死的。第一批 320 篇没过线，这是否定结果，我们照实留着。第二批 294 篇是没看过的新数据，两条都过线。其中一条是刚好过，下界离 0 很近。"

## 3:40–4:30 诚实的部分

"三件事要说清楚。第一，小队在最后写报告那一步卡住了，报告是人工整理的，失败的调用都记在仓库里。第二，一名 AI 成员认为脚本里有个减 1 是错的，我实测了 5 篇，证明减 1 是对的。第三，样本只有 614 篇，没分学科，离原论文的规模差得远。"

## 可能被问到

- **为什么信计数法？** 两批共 15 篇逐条重数，全部一致；公式等价有代数推导和 20 万组数值验算。
- **AI 说没问题算验证吗？** 不算。我们的依据是独立重算出来的数字、已知答案的自检、和文献原文。
- **26 小时是真的吗？** 是推算。用引用记录总数除以每页 200 条，再乘实测的单次请求耗时，没有真的那样抓过。
- **数据是模拟的吗？** 不是。全部是 OpenAlex 的真实数据，csv 和日志都在仓库里。
