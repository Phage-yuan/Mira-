## 作品标题

【B·组会前一晚｜计算机/数据科学】团队越大，论文越不颠覆？——真实数据复现小队

## 目标问题

要讲 Wu、Wang 与 Evans（Nature 2019）"大团队发展、小团队颠覆"这篇论文的研究生，想在组会前自己验证一遍：换成公开数据库 OpenAlex、随机抽一批论文，这个方向还成立吗？

现在的做法是把引用记录逐条抓下来再算颠覆性指标。我们的第一批 320 篇涉及 4,070 万条引用，至少 20.4 万次请求，按实测速度推算约 26 小时；而且一个人抓数据、算统计、自己检查自己，没有独立验证。

## 已实现功能

1. 计数法算颠覆性指标 CD5：每篇论文只发 3 次请求，不用逐条抓引用。614 篇共 1,845 次请求。
2. 自带量具自检：随机抽若干篇用笨办法逐条重数，第二批 10/10 一致，第一批 5/5 一致。
3. 在 Mira 上搭了 5 人专家小队并真实跑通：主管、文献核对、数据工程、统计分析、独立审核，两路并行加审核返工。
4. 判定标准先于数据写死（PROTOCOL.md），全程未改。
5. 独立审核：审核员不看分析代码，用 numpy 和 statsmodels 重算，斜率相差不超过 1.5e-16。
6. 结果：在没看过的 294 篇新数据上，两条检验都过线；第一批的否定结果照实保留。
7. 一条命令重跑：make repro 不联网重算全部结论；make demo 现场联网抽 5 篇演示。

## 核心技术方案

- 平台：Mira Science 专家小队（Agent Squad），自定义三阶段配合模式：并行（文献核对 + 数据抓取）→ 统计分析 → 独立审核与人工确认，审核不过最多返工 2 次。
- 数据流：OpenAlex 公开接口 → fetch_cd5.py（随机抽样，计数法算 A、B、J 和 CD5，带逐条自检）→ batch2_mira.csv → analyze.py（线性回归斜率 + 自助法 10,000 次的 95% 区间，按写死的标准给判定）→ 独立审核员另写脚本重算对比 → 人工复核 → 报告。
- 模型：使用 Mira 平台内置的模型，我们没有另外指定或调用别的模型。
- 代码：Python 3，只用标准库，无第三方依赖。
