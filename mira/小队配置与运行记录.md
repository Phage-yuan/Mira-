# Mira 专家小队：配置与运行记录

平台：Mira Science 桌面版 1.0.1（深度原理），云端共享环境（Shared Cloud）。
会话标题：复现 Wu 2019 团队规模与颠覆性研究。
时间均为运行当天的美国中部时间（CST，2026-11-21），括号内为北京时间。

## 一、小队配置

小队名：论文结论复现 Squad。由一段文字描述自动生成 5 名成员，技能由平台自动分配，未手动改动。

- 复现主管（Lead）：冻结判定标准、分派任务、审阅产物、全部检查通过才收尾。技能：planning-with-files。
- 文献核对员：对照一手文献核对原论文和 CD 指标定义，给出准确出处或写明查不到。技能：literature-search。
- 数据工程师：对 OpenAlex 运行给定的 Python 脚本，保存原始输出和日志，不改逻辑。技能：project-db。
- 统计分析员：按 PROTOCOL.md 的固定口径跑回归、自助法区间、出图。技能：scientific-visualization。
- 独立审核员：用另一套工具从原始数据重算关键数字，逐项对比，对不上打回。技能：project-db。

小队卡片上另外显示的技能标签：peer-review、research-fetch。

## 二、配合模式

模式名：复现审核配合模式（3 个阶段，2 条返工分支）。

1. 阶段 1，并行：文献核对员、数据工程师同时开工；主管汇总。
2. 阶段 2：统计分析员按固定口径跑分析和画图；主管汇总后交独立审核员审核，不通过打回阶段 2，最多返工 2 次。
3. 阶段 3，独立审核与人工确认：独立审核员重算并出对比表；由用户确认，不确认则回到阶段 3。
4. 结束：主管汇总交付。

**人工改动（照实记录）**：配合模式由一句话自动生成。自动生成的草稿里，阶段 3 叫"人工检查确认"，成员是统计分析员，独立审核员没有出现在任何阶段。人工把阶段 3 改名为"独立审核与人工确认"，成员换成独立审核员，并写了该成员的任务说明。原因：让分析的人自己整理结果给人确认，等于没有独立审核。

## 五、失败的调用与异常（照实记录）

1. 生成配合模式第一次失败，提示"Generation failed. Please try again."，原样重试一次后成功。
2. 数据工程师第一次匿名探测 OpenAlex 额度，返回 HTTP 429（同一出口 IP 的当日免费额度已用完）。抓取脚本随后检测到云端环境自带的 `OPENALEX_API_KEY`，走了密钥额度。这把密钥不是我们提供的。
3. 独立审核员的"发布对比表"任务多轮自动恢复后仍阻塞，主管暂停重试。重算本身已在此前完成并通过。
4. 人工的一条回复发送失败，重发后送达。
5. 主管在规划和状态汇报阶段用的是英文（它说明该阶段界面语言固定为英文），产物为简体中文。
